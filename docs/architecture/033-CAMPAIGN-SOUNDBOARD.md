# 033 — Campaign Soundboard

Status: implemented (replaces the old Listen placeholder; workspace id stays `listen`, label "Soundboard").

## What it does

A grid of sound pads for live play, grouped into three channels:

| Channel  | Behaviour                                                                 |
|----------|---------------------------------------------------------------------------|
| Music    | One track at a time. Starting another fades the current one out (600 ms). |
| Ambience | Layers: any number of ambience pads play together.                        |
| Effects  | Overlap freely.                                                           |

Music, ambience and effects all play at the same time. Each pad has a name, an audio file, a channel,
its own volume slider and a Loop/Once toggle on its tile (music and ambience default to Loop, effects to
Once). The mixer has a master fader plus one fader per channel; a pad plays at `master × channel × pad`.
Looping pads fade out when stopped; **Stop all** silences everything immediately. Pads whose file
disappeared are shown as "missing file" and cannot play.

## Built-in sounds

Twenty synthesized sounds ship with the app in `static/soundboard/` (about 2 MB of Ogg Vorbis) and are
referenced from a layout as `builtin:<name>.ogg`: music (Tavern Jig, Travel March, Dungeon Drone,
Battle Drums, Suspense), ambience (Rain & Storm, Wind on the Road, Forest, Cave Drips, Night Camp,
Ocean Waves, Eerie Atmosphere, Tension Bed, Epic Swell) and effects (Sword Clash, Spell Cast, Thunder,
Magic Chime, Door Creak, Monster Growl). They are generated by `scripts/make-soundboard-sounds.py`
and released CC0, so there are no third-party rights. A campaign with no `soundboard.json` starts with
one pad per built-in sound; nothing is written until the GM changes the board.

## Storage (file-authoritative, no database)

```text
<Campaign>/Assets/Audio/
├── soundboard.json        pad layout and mixer levels
├── Music/…                optional subfolders, any depth
└── *.mp3|ogg|opus|wav|flac|m4a|aac|webm
```

`soundboard.json`:

```json
{
  "format": "catalyst-soundboard",
  "version": 1,
  "master_volume": 0.8,
  "channels": { "music": { "volume": 1 }, "ambient": { "volume": 1 }, "effects": { "volume": 1 } },
  "pads": [
    { "id": "pad-<uuid v4>", "label": "Tavern", "file": "Music/Tavern.ogg",
      "channel": "music", "loop": true, "volume": 1 }
  ]
}
```

- `file` is relative to `Assets/Audio/`, or `builtin:<name>.ogg`. The backend refuses absolute paths, `..`, non-audio
  extensions and symlinks that resolve outside the folder.
- The file is written atomically, and fields it does not know are kept. A layout from a newer version
  is refused rather than overwritten.
- Deleting `soundboard.json` only resets the board; the audio files are plain files any player can use.
- **Import audio** copies picked files into `Assets/Audio/` and never overwrites (a clash becomes
  `Name (2).ext`). Files dropped into the folder by hand appear after **Rescan**.
- Pad ids use a `pad-` prefix with a UUID v4. They are board-local, not core document IDs.

## Offline playback

Audio bytes are read by the Rust command `read_soundboard_audio` and returned as a raw binary IPC
payload. The UI wraps them in an in-memory `blob:` URL and plays them with `HTMLAudioElement`, one
element per playing pad. Built-in sounds play straight from the app bundle. No remote assets, no
network requests. The CSP gains `media-src 'self' blob:` for this.

Commands: `list_soundboard_audio`, `read_soundboard_audio`, `load_soundboard_layout`,
`save_soundboard_layout`, `import_soundboard_audio` (`src-tauri/src/soundboard.rs`,
`src-tauri/src/commands/soundboard.rs`). UI: `src/lib/components/SoundboardWorkspace.svelte`,
`src/lib/soundboard.svelte.ts`.
